The problem, and who has it

The pieces exist. The joins are done by hand.

Who has it

MBA students recruiting for a summer internship, starting with the author (Yale SOM, Summer 2027): many organisations at once, each with its own deadlines, plus the alumni, recruiters and classmates who can open a door.

How it is solved today

At least seven places: a tracker, email, LinkedIn, WhatsApp, iMessage, job boards and school platforms. The student searches each board, looks up who works there and who is an alum, retypes what matters and preps each coffee chat from scattered notes.

Why it matters

A missed follow-up or a deadline seen two days late cannot be bought back. Only one place holding openings, people and conversations sees that they concern the same internship.

Layered defences, enforced in code
1Shield: hidden text and lines that read like instructions to an AI are removed before any model sees them (0 tokens); white 1-px text was removed too (run 2bbe610b4159).
2Records keeper: rejects any quote, person, link or id not in the source; keeps a web result only if its page shows it; never opens LinkedIn, Handshake, 12twenty or Symplicity.
3Nothing is sent: no agent has a sending tool; drafts wait in an Outbox.
4Caps: 300,000 tokens and 20 web requests per student a day (429); 6 requests and 60,000 tokens per agent run; ≤4 delegations; a kill switch; another student's data returns 404.
✓Shown working: 80 automated tests pass with no key; a live check passed 19 of 19 (before the web features); two adversarial reviews, confirmed findings fixed.

Honest limit: the shield is pattern matching, and pages read by OpenAI's search are not shielded. So web agents only propose typed results and the keeper re-reads each page: the worst case is a wrong card the student can see, never a message sent.

Limits and next steps

What does not work yet, and the next month

Not yet
No user test yet; the first tester is the author, who built it.
“The whole web” is OpenAI's search, 4 job-board APIs and careers pages that allow reading; never LinkedIn, Handshake, 12twenty or Symplicity; JavaScript-only pages cannot be confirmed.
Alumni only from public pages; the alum flag is the agent's reading (code checks the name, not the school); the alumni directory is not read.
Web costs capped per day, not per request: one request made 8 searches; no site-wide cap on search fees.
Chat auto-sync half verified; free hosting sleeps: a 32 s cold start.
With another month
  1. Measure with 5 to 10 classmates: times, ratings, quotes.
  2. An evaluation set: 50 fictional messages and postings plus web searches with known answers.
  3. Enforce the web budget in code: per request and site-wide.
  4. A career-office pilot: always-on hosting ($32 a month), the school's postings and alumni directory.
