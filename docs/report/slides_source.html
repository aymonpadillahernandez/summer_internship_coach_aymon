The problem, and who has it

The information is not missing. It is scattered.

Who has it

MBA students recruiting for summer internships: many organisations at once, each with its own deadlines, and alumni, recruiters and classmates who can open a door.

How it is solved today

The student is the integration layer: they read every channel, retype what matters into a spreadsheet or a tracker, and decide from memory where this week goes.

What it costs

Attention; follow-ups promised in a chat that never reach the tracker (not yet measured); and $29 to $40 a month for a paid job-search plan (Teal, Simplify, LinkedIn Premium, Huntr) that covers only part of it.

What this app does differently
1One memory across channels

Mail, chats, exports, invites and postings land on the same two boards, each person linked to the internship they can help with.

2A weekly plan with evidence

Plan my week ranks open actions with why now and a first step; every saved fact carries the exact quote it came from, checked in code.

3Read-only by design

No agent has a sending tool; drafts wait in an Outbox. One wrong message to a recruiter costs more than any time saved.

Where we are weaker: no résumé or autofill tools, far less job data than LinkedIn or Simplify, and chat auto-sync needs a Mac.

Layered defences, enforced in code
1Shield: hidden text and lines that read like instructions to an AI are removed before any model sees them, and shown to the student (0 tokens).
2Records keeper: rejects any quote, person, link or record id that is not in the source.
3Nothing is sent: no agent has a sending tool; drafts wait in an Outbox for the student.
4Isolation and budgets: another student's data returns 404; 300,000 tokens per student per day, then 429; a kill switch; caps on loops.
✓Shown working: 76 automated tests pass with no key; a live check of every agent and guardrail passed 19 of 19; two adversarial reviews, all confirmed findings fixed.

Honest limit: the shield is pattern matching, so new wording could get past it. The keeper would still accept only what the pasted text literally says, with its quote, so the worst case is a wrong card the student can see and correct; no agent can send anything.

Limits and next steps

What does not work yet, and the next month

Not yet
No real user test yet. The first tester will be the author, who is also the builder; one tester is not a sample.
Chat auto-sync is half verified. Gmail syncs on its own; iMessage and WhatsApp wait for Full Disk Access, not yet verified. It needs a Mac.
Free hosting sleeps (cold start 32 s), and GitHub runs the keep-awake schedule only sporadically.
Not measured: retrieval recall at scale, the chat filter's misses, and a Duolingo posting the scout read but did not save.
With another month
  1. Measure: run the protocol with 5 to 10 classmates and publish times, ratings and quotes.
  2. An evaluation set: 50 fictional messages and postings with known answers, scored on every change.
  3. One-click connection: a signed Mac menu-bar app instead of a Terminal script, and the known interface fixes.
  4. A career-office pilot: always-on hosting ($32 a month), school sign-in, school postings with permission.
